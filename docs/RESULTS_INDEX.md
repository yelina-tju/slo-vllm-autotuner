scheduled goodput提升19.25%/18.95%，但增加978/986次服务违约；不能宣称全程
SLO保证，也不能把这一1.5B独立扩展数字移植到下面的V1 7B结论。

主要可复核结果：

- 1.5B，五配对种子：canary 相对 binary 的 goodput 差为 −0.549 req/s，95% 配对 t 区间 [−0.802, −0.295]；满容量恢复多 39.80 秒。
- 7B，四配对种子：goodput 差为 −0.17447 req/s，区间 [−0.27319, −0.07575]；满容量恢复多约 41.96 秒。
- 7B，两个持续延迟故障种子：故障暴露 229→186、242→186；这是包含后续配置回退的全故障过程计数，不能当作单独第一阶 canary 的因果效应。
- 7B，真实执行器：正常配置切换 71.681 秒；目标启动失败后源服务恢复 242.069 秒（包含 180 秒目标健康超时）。均验证了暂停准入、排空、健康、预热和恢复后真实推理。

Oracle 是预知负载边界、受固定策略目录和执行器约束的参考策略。7B static aggressive 的 goodput 更高，同时完成但超时请求更多；不能把 Oracle 叫作所有策略的数学上界。

同系列 1.5B→7B 是模型规模验证。尚不支持跨架构、跨 GPU 或生产故障发生概率的声明。持续故障触发的 mbt1024→mbt2048 回退与 canary 第二阶 9→6 是不同路径，后者仍仅有 CPU 契约证据。
