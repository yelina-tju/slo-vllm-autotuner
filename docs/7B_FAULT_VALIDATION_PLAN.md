## 不占 GPU 的独立测试

入口：`python scripts/check_7b_fault_contract.py`。仅依赖 Python 标准库和现有控制器模块；读取已冻结的 7B 容量/SLO，在临时目录生成测试 catalog，使用逻辑时钟和合成窗口。输出 JSON 到 stdout，不写生产配置、不连接服务、不启动子进程。

已执行 12 项断言全部通过，覆盖六类场景：

| 场景 | 通过标准 |
|---|---|
| 健康逐级恢复 | 首次恢复到 6；每两个含新成功 ID 的窗口升到 9、12；无需重启 |
| 重复成功证据 | 同一组成功 ID 的窗口重复出现，不增加晋级确认 |
| canary 一级故障 | 重复违规 ID 不确认；第二组新违规证据触发 6→3 |
| binary 故障 | 相同规则触发 12→3，便于与 canary 比较 |
| canary 二级故障 | 已验证 6 后升到 9，持续违规返回 6 |
| 缺失指标与冷却 | 无指标不能晋级/回滚；回滚后冷却期间禁止马上升容 |

这些是状态机契约证据，不能据此填写“实际慢请求减少数量”或“真实 GPU 故障恢复时间”。确定性场景跑一次即可；重复同一逻辑输入不算独立样本。

另有独立合成 HTTP/SSE 服务 `scripts/fault_7b_sse_fixture.py`，执行 `python scripts/fault_7b_sse_fixture.py --self-test` 可在本地随机端口验证健康响应、首 token 延迟、缺少 [DONE] 的截断响应。三例已通过，测试后服务自动退出。它不转发到 vLLM；把它接到 gateway 做端到端校验，以及真实 GPU 注入层仍是下一阶段工作。延迟采用单调时钟截止时间循环，避免单次 sleep 提前返回导致故障强度不足。

## 同卡验证的最小数量：8 次

启动条件：当前 16 次最终实验全部结束；审查 trace/payload、终态、控制错误及缺失恢复终点；备份结果；确认没有现存 GPU 作业后，人工执行独立故障任务。没有安排自动启动。

| 组别 | 数量 | 目的与通过标准 |
|---|---:|---|
| 无注入健康对照：binary、canary | 2 | 经过同一个故障注入层，无延迟；服务健康，canary 到达 12，无额外重启 |
| 首级持续延迟：两个新种子 × binary/canary | 4 | 每个种子复用同一开放环输入与注入规则；出现两次新违规证据后回退到 3；冷却阻止重试；终态未暂停、服务健康 |
| 强制不同配置切换，正常启动 | 1 | 在有在途请求时切换 1024→2048；暂停期间拒绝新准入，在途排空后停旧服务，再启动/探活/预热并恢复；无孤儿进程 |
| 同一切换，目标启动失败 | 1 | 只对目标启动注入一次失败；恢复原模型/配置，健康检查和真实完成请求通过；准入恢复；事务明确记录失败及恢复 |

两个故障种子拟固定为 131、132；健康和执行器场景分别用独立标记 health、restart_ok、restart_fail。每个请求实验固定 330 秒；启动失败的事务总预算 480 秒（排空 120、目标启动 180、原服务恢复 180），超时判失败并保留日志。实际恢复超时不得通过增加阈值改写同一次结果。

故障时序：共同 trace 从 mixed 安全策略起步，随后发送 short 请求以触发恢复。以首次成功的升容事务为相对起点，接下来固定 60 秒对已准入请求注入额外首 token 延迟，延迟取冻结 short TTFT SLO 的 1.25 倍。该设计比较“升容后遭遇同样持续故障”的响应，不等价于同一绝对时刻的生产故障。若未发生升容，记为未到达故障触发点，不能伪造一个故障成功样本。

注入层应保留原请求 ID、SSE token/[DONE] 边界，记录注入起止、原始与注入后时间戳。健康对照必须通过同一层，以评估额外转发开销。故障独立驱动脚本的 HTTP/GPU 接线仍需在本轮结果审查后实现并验证；当前已经可运行的是 CPU 契约脚本。

8 次足以构成最小机制验证，不足以给生产故障概率、稳定收益置信区间或跨架构泛化结论。若两组配对暴露差异方向不一致，保留结果并分析，不以更换种子补成“成功”。二级故障当前只覆盖 CPU 契约；若要宣称真实 HTTP 二级回滚也已验证，追加 2 次，不包含在上述最小 8 次中。

## 输出与判定

每次保存配置/模型身份/代码哈希、请求 JSONL、事件 JSONL、事务日志、服务日志、运行前后进程和健康状态。结果区分 `passed`、`failed`、`not_reached`。

核心量：从注入起点到回滚生效的时间；故障期间已准入且不满足 SLO 的请求数；429/503；goodput；暂停时长；在途请求数；原服务恢复时间。机制通过要求动作顺序正确、证据新鲜、恢复健康。收益声明则额外要求实际观测到 canary 暴露更少；不能把“6 比 12 小”直接当作实测降幅。
